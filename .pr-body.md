## Summary

Companion release to smart-terminal-mcp **1.2.41** — multi-line command safety for the persistent PTY, from a real incident where `gh pr create --body @'...'@` (here-string) left pwsh stuck at a `>>` continuation prompt and burned the timeout.

### What's new

- **Guard guidance in `terminal_exec`**: the tool description now warns that multi-line here-strings (`@'...'@`) and heredocs (`<<EOF`) are rejected by the core (1.2.41) and points at the workaround: write the payload with `terminal_write_file`, then `--body-file` / `< file` / `Get-Content -Raw`.
- **`maxOutputBytes` param on `terminal_exec`** (1 KB–1 MB, default 128 KB from the core): caps total output with a head/notice/tail split; forwarded through `core.ts` and typed in `upstream.d.ts`.
- **README: "Multi-line payloads" section** — why here-strings/heredocs can't survive PTY line-processing, the file-based pattern, and how the new continuation-prompt hints look on timeout.

### What you get from the 1.2.41 core bump (already merged upstream, PR pungggi/smart-terminal-mcp#18)

- `terminal_exec` fails fast on here-strings/heredocs with an actionable error instead of hanging.
- Timeout hints name the stuck continuation prompt (`>>` / `>` / `More?`) instead of the generic "still running".
- Linux/macOS pwsh sessions no longer hang on the first command: DSR/DA terminal-query answering, prompt-readiness wait before any input, bracketed-paste wrapping of exec writes — four PTY-host bugs fixed, verified against real pwsh on ubuntu CI.
- Output caps, accurate PowerShell/cmd exit codes, winpty handle-leak release.
